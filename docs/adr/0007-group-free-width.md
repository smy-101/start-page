# 组宽改自由宽:档位制退役(复活 ADR-0005 选项 C,对齐待办卡宽 v10)

group-span-decouple(schema v7)把组宽做成 1–6 档位:拖柄松手吸附档位边界、
键盘步进一档、渲染宽由档位几何推导不存 px。用户实操反馈:**阶梯式调宽不顺手,
要跟待办卡一样拖到任意宽**(待办侧 v9 档位制同样一轮调校后退役,经验可平移)。
定案 2026-12(`.scratch/group-width-free/`):ADR-0005 当年弃选项 C 的三条顾虑
(拖柄吸附、导入钳界、装箱占槽)在待办卡 v10 已全部被「px + 16px 网格吸附 +
钳界函数」方案消化,组宽照搬同一语言。

## Considered Options

- **A · 维持档位(v7 现状)**:吸附/钳界/装箱整数口径最简;但档位边界
  (222/412/…/1172)对用户是黑盒,两卡(组 vs 待办)调宽语言不一致。
- **B · 加密档位**:治标,档位间的「差一点」永远存在;弃。
- **C · 自由宽 px(选定)**:`Group.width?: number`(schema v12→v13,缺省 =
  从每行条数推导装满,存量零改写);拖右缘连续调宽、松手 16px 网格吸附、
  键盘 ←/→ 步进一格、徽标/aria 报 px——与待办卡宽 v10 逐字同语言。
  v7 及更早备份的 span 按旧档位数学换算为 px(渲染逐字不变)。

## Consequences

- **模型**:`width` 优先、存在即钳回 [222, 2400];缺省推导 = 装满
  (`groupCellsForWidth` 为 `groupWidthOf` 的逆,缺省条数随宽自适应)。
  ADR-0005 的两条用户决策**保留**:拖窄装不下时每行条数自动跟降(写路径);
  表单改条数组宽只升不降(抬宽基准 = 装满条数的宽)。
- **界限**:下限 222 = 单格恰装(groupWidthOf(1),再窄装不下一格收藏;
  非 16 对齐是接受的——吸附只发生在拖柄松手);上限 = 画布宽
  (缩画布至放不下时收窄,同待办卡;2400 绝对界只是哨兵)。
- **写路径**:`setGroupWidth`(拖柄/键盘,钳界 + 条数自动降 + 重钳 x)、
  `setGroupColumns`(表单,只升不降,物化宽)、`setCanvasWidth` 收窄、
  导入恢复换算/收窄/防御钳——全部 store 收口,16px 对齐只在组件松手吸附。
- **迁移**:v12→v13 按档位数学换算 px、剥离 span;终末修复剥残遗 span、
  钳/剥非法 width、合法条数装不进钳后宽时抬宽到恰装(不丢排版)。
- **词汇**:GLOSSARY「组宽档位」改写为「组宽」;ADR-0005 的解耦决策
  (宽度与条数两个旋钮)继续有效,仅宽度侧的实现从档位换轨为 px。

# 待办卡:画布第二种卡片,白板门禁为勾选开洞

用户提案「新增 todo,变成 todo 卡片也放在白板区块(画布)里」。grilling 两轮
十三问定案(2026-10-30):**待办卡**成为画布上与分组卡并排的第二种卡片——
清单卡(标题 + 可勾选条目),自由定位、对齐吸附、钳界、自动整理与分组卡同体系;
同时给 ADR-0004 的门禁开了**唯一的洞:日常态可勾选/取消勾选**,其余编辑
(建卡/删卡/删条目/改文字/拖动/卡内排序/改名)仍锁白板模式。

## Considered Options

- **卡片形态**:清单卡(选定)vs 便签式一事一卡(迅速铺满画布、与分组卡粒度
  失衡)vs 待办专属区块(割裂「坐标即布局」的白板范式)。
- **日常态交互**:全锁进门禁(待办失去日常意义)vs 全开(误触风险回到门禁
  初衷)vs **仅勾选开洞(选定)**:勾选是内容消费、与「点开收藏链接」同级,
  不是结构编辑。
- **持久化**:进 `BookmarkState` 顶层 `todos` 数组(schema v8,随 JSON 备份
  导入导出;选定)vs 易失存储(换机/重装即丢)。

## Consequences

- **范式**:画布不再只装分组卡。待办卡 = 定宽 `CARD_W` 的矩形(v1 无档位、
  无调宽拖柄),按同几何参与吸附/钳界/装箱整理。
- **门禁例外是刻意为之**:日后看到「白板模式=唯一编辑入口」却有待办勾选常开,
  不是 bug;收回此洞是破坏性变更(用户会依赖日常勾选)。GLOSSARY「白板模式」
  「待办卡」「画布」已同步口径。
- **语义边界**:待办卡不装收藏、不是分组;删除**不进收集箱**(收集箱语义
  专属收藏);整卡删除无确认(与删分组同级);完成条目划线沉卡底、不自动
  清除;空卡保留;条目数与文本长度不设上限。
- **v1 明确不做**:跨卡移动条目、待办文本进搜索结果(搜索结果 UI 是收藏形状,
  无可跳转目标)、待办卡自选色(分组色是「收藏容器」的视觉语言,待办卡以
  中性配色一眼区分)。
- 实现细节(字段形状、DOM/Tab 序混排、DnD 复用)在工单阶段定,不入本篇。

**补记 2026-10-31(todo-daily-add,门禁再开一洞)**:「仅勾选开洞」退役——
每次添加待办都要进出白板模式,高频路径背上门禁成本(用户反馈)。门禁再开
一洞:**日常态可添加待办条目**,入口为卡尾常驻输入框(与白板模式同款);
空卡的「暂无待办」提示退役,由输入框直接替代(空卡正是最需要加条目的卡)。
改文字/删条目/卡内排序/改名/建卡/删卡/拖动仍锁白板模式(低频结构编辑,
门禁初衷防误触不改)。原文「门禁例外是刻意为之、收回是破坏性变更」的
论断同适用于添加洞;新条目落位沿用 store 现行语义(插未完成区末,完成区
沉底)。GLOSSARY「白板模式」已同步。详 `.scratch/todo-daily-add/`。

**补记 2026-11-13(todo-card-size-color,宽与卡色;自由宽调校 11-14)**:
两项 v1 决定退役——「定宽 CARD_W、无调宽拖柄」与「不做待办卡自选色」。
**宽**:待办卡宽可调且为**自由宽**(用户定案,不设档位;档位制两轮
调校后退役),钳 [240, 768] px(缺省 = CARD_W 存量零改写;下限 240 为
紧凑卡——勾选框 + 约 12 字/行,上限 768 ≈ 两倍缺省宽——宽过两倍缺省
即不像卡;均 16 倍数),白板模式拖卡右缘连续调宽、松手 16px 网格吸附、
键盘 ←/→ 步进一格(同分组交互语言);缩画布宽至放不下时收窄。演进:
初版档位制(6 档 +190 → 收窄 5 档 +95)经用户反馈定案自由宽,schema v10
迁移按旧档位数学换算为 px(v9 未发布,仅本地开发版数据)。
**卡色**:推翻「待办不沾组色」的初衷考量——缺省仍是中性白卡
(「一眼区分」的缺省观感不变),染色是用户主动行为;表达为卡面底染 12%

- 边框微带色(组托盘 16%:托盘沉、白卡浮的分层语言保持),勾选框/指示线
  保持墨色(色板含浅粉彩,白勾浅底不可读;勾选是内容消费);空串写回
  复位中性。调宽/换色锁白板模式(低频结构编辑,门禁口径同删改)。
  GLOSSARY「待办卡」「待办卡宽」已同步。详 `.scratch/todo-card-size-color/`。

**补记 2026-11-16(todo-height-archive,定长高与归档)**:两项演进——
**定长高**:待办卡高可调且为自由高(缺省 = **自适应**随内容长、列表
约 18 行起内部滚动,存量零改写),钳 [176, 720] px(下限 = 卡头 + 约三行

- 添加行,上限 ≈ 略高于自适应观感上限);定长时卡面纵向 flex、条目
  列表区滚动、添加行常驻可见。交互与调宽同语言:白板模式拖卡底缘连续
  预览、松手 16px 网格吸附、键盘 ↑/↓ 步进一格(schema v11);**锁白板
  模式**(低频结构编辑,门禁口径同调宽)。高不随画布宽收窄(画布向下
  无界)。
  **归档**:门禁第三洞——卡头归档钮**一键清除该卡全部已完成条目**,
  **两模式可见、日常态直达**(勾选消费的自然收尾是清理,高频内容路径,
  论证形状同 todo-daily-add 的添加洞);点击直接清除无确认(同「删条目/
  整卡删除均无确认」口径),无已完成条目时禁用;余条目保序重排。不做
  独立归档存储(清除即删,不进收集箱)。GLOSSARY「待办卡」「待办卡高」
  「归档」「白板模式」已同步。详 `.scratch/todo-height-archive/`。

**补记 2026-11-16 二次(todo-height-archive,钉住切换 + dist 陈旧教训)**:
定长一经设置原无回自适应的路径——白板模式卡头新增**钉住钮**
(Pin/PinOff 图标,与调色/删除并列):自适应态点击 = 以**实测高**吸附
16px 网格落定长(jsdom 实测 0 → 下界兜底);定长态点击 = 写回
undefined 剥离字段回自适应(同 recolorTodo 空串复位中性的语义形状)。
用户报告「定长时输入框/标题被条目挤出、卡不能滚」经查为 **dist 陈旧**:
CRXJS dev 只把 JS 写入 dist、CSS 走 HMR 内存注入,dev server 停后扩展
加载到「新 JS + 旧 CSS」——定长逻辑生效而 flex 滚动样式缺失。教训:
给扩展装新产物一律 `npm run build` 后重载,勿直接吃 dev 会话的 dist。

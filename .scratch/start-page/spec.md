# Spec: start-page 浏览器收藏初始页

**Status:** ready-for-agent

## Problem Statement

浏览器默认新标签页只是一个搜索页,而用户收藏的网页散落在书签栏和层层文件夹里:找常用网站要翻、组织方式只有文件夹嵌套一种、想备份或迁移到别的浏览器只能靠浏览器自带的导入导出,分组和整理能力僵硬。用户想要一个自己掌控的起始页:打开新标签页第一眼就是自己整理好的收藏,按自己的方式分组,数据随时可以带走。

## Solution

一个 Chromium (Chrome/Edge) Manifest V3 扩展,把新标签页覆盖为「初始页」:收藏按分组分区展示成网格,顶部搜索框实时过滤收藏、回车跳搜索引擎,右上角齿轮进设置。提供三种收藏入口:初始页内手动添加、右键菜单"收藏到→某组"、工具栏图标一键收藏(图标随当前页是否已收藏切换状态)。数据存插件自有存储(`chrome.storage.local`),支持 JSON(无损备份)/HTML(通用迁移)双格式双向导入导出。界面中文,深浅色跟随系统。

## User Stories

### 初始页

1. 作为用户,打开新标签页即看到收藏网格,以便一眼直达常用网站
2. 作为用户,收藏按分组分区展示,每组有名字和颜色可辨识
3. 作为用户,点击收藏卡片即打开该网页
4. 作为用户,在搜索框输入即实时过滤收藏(匹配标题/URL/备注,不区分大小写)
5. 作为用户,搜索框内回车即用默认搜索引擎搜索输入的词
6. 作为用户,界面跟随系统深浅色自动切换
7. 作为用户,界面语言为中文

### 分组管理

8. 作为用户,我能新建分组(名字 + 颜色)
9. 作为用户,我能重命名分组
10. 作为用户,我能修改分组颜色
11. 作为用户,我能拖拽调整分组之间的顺序
12. 作为用户,我能把收藏拖拽移动到另一个分组
13. 作为用户,我能在组内拖拽调整收藏顺序
14. 作为用户,我能折叠/展开分组
15. 作为用户,删除分组时其中的收藏自动回到收集箱,不会丢数据
16. 作为用户,收集箱是始终存在的默认分组,不能被删除

### 收藏入口与编辑

17. 作为用户,我能在初始页上手动添加收藏(输入 URL/标题/备注,选分组)
18. 作为用户,浏览任意网页时能右键"收藏到 → 某分组"
19. 作为用户,浏览任意网页时能点工具栏图标一键收藏到收集箱
20. 作为用户,当前页已收藏时,工具栏图标显示"已收藏"状态(实心勾选)
21. 作为用户,当前页未收藏时,工具栏图标显示"未收藏"状态(空心)
22. 作为用户,对已收藏页面再点一次图标即取消收藏
23. 作为用户,收藏/取消收藏有即时的视觉反馈(图标瞬时反馈)
24. 作为用户,我能编辑收藏的标题/URL/备注/所属分组
25. 作为用户,我能删除收藏
26. 作为用户,网站图标取不到时,收藏卡片显示首字母色块作为回退

### 导入导出

27. 作为用户,我能导出 JSON 完整备份(含分组颜色、顺序、备注)
28. 作为用户,我能导出 Netscape HTML 书签文件供其他浏览器导入(分组映射为文件夹)
29. 作为用户,我能导入 JSON 并选择"合并"(按 URL 判重跳过已存在)或"替换全部"(备份恢复)
30. 作为用户,我能导入浏览器导出的 HTML 书签文件(文件夹映射为分组,URL 判重跳过)
31. 作为用户,导入完成后能看到"新增 N 条、跳过 M 条"统计
32. 作为用户,我能从浏览器原生书签一次性导入(chrome.bookmarks)

### 设置

33. 作为用户,我能在设置中选择搜索框默认搜索引擎(Google / Bing / 百度,默认 Bing)
34. 作为用户,我能在初始页右上角齿轮进入设置

### 数据

35. 作为用户,我的数据仅存本地(chrome.storage.local),不上传任何服务器
36. 作为用户,收藏增长到数千条后初始页依然流畅

## Implementation Decisions

- 仅 Chromium MV3(ADR-0001:自有存储,不用原生书签作数据源)
- 初始页通过 `chrome_url_overrides.newtab` 覆盖;不注册 action popup,使 `chrome.action.onClicked` 可用于一键收藏
- 自有数据模型:单一状态对象 `{ schemaVersion, groups, bookmarks }`;分组 `{ id, name, color, order }`,收藏 `{ id, url, title, note, groupId, order }`;收集箱是 id 固定为 `inbox` 的保留组
- URL 判重基于规范化 URL:协议与主机小写、去 fragment、去默认端口、根路径去尾斜杠;判重逻辑只有一处,手动添加与导入共用
- 持久化用 `chrome.storage.local`,经存储适配器接口注入领域层;领域层为纯 TypeScript,不 import 任何 `chrome.*`
- 工具栏图标状态:`tabs.onActivated` / `tabs.onUpdated` 事件驱动 service worker 查当前 tab URL 是否已收藏,`chrome.action.setIcon({ tabId })` 切换两套图标(空心/实心)
- 右键收藏:`chrome.contextMenus` 动态子菜单列出收集箱与各自定义分组,分组增删改名时重建菜单
- favicon:manifest 声明 `"favicon"` 权限,图片 src 用 `_favicon` 端点(本地缓存、离线可用);加载失败回退首字母色块;不使用任何网络图标服务
- 导出 JSON 为上述完整状态;导出 HTML 为 Netscape 书签格式,分组→一层文件夹
- 导入 HTML 用 DOMParser 解析(纯函数,可在测试环境运行);JSON 导入"合并"跳过重复、"替换全部"清空重写;两种导入与手动添加走同一条判重路径
- 技术栈:Vite + TypeScript + React,@crxjs/vite-plugin 2.x 打包;测试 vitest
- 搜索过滤:标题/URL/备注不区分大小写子串匹配;回车跳默认引擎(引擎 URL 在设置中选择,默认 Bing)
- 主缝隙(seam):领域层纯 TS 模块。收藏/分组全部业务逻辑(增删改查、判重、合并/替换导入、移动、组删除回收)都在这层,存储与 Chrome API 通过注入的适配器隔离

## Testing Decisions

- 好的测试只测外部行为(领域层公共 API 的输入输出),不测内部实现细节
- 领域层为测试主战场,vitest 全覆盖:增删改查、URL 规范化判重、合并/替换导入、删除组回收集箱、跨组移动与排序,以及不变量"每个收藏必属且仅属一个现存的分组"
- HTML 导入导出:基于 DOMParser 的纯函数,用真实浏览器导出的 HTML 样本作 fixture 测试
- React UI:轻量渲染测试(关键组件渲染不炸、关键交互冒烟),不追求组件级全覆盖
- 真实扩展行为:用 chrome-devtools MCP(Windows Chrome)加载 dist 冒烟——新标签页覆盖、工具栏图标状态切换、右键收藏、导入导出回环
- Chrome API 适配器不单测(薄 mock 层),靠上述冒烟覆盖
- 本仓库无既有测试,本 spec 建立测试先例

## Out of Scope

- Firefox 支持
- 自动云同步 / WebDAV(v2+ 可能的方向)
- 嵌套分组、一个收藏属于多个分组(标签)
- 时钟、天气等起始页小组件
- 工具栏点击弹窗选组收藏(一键只进收集箱)
- 浏览器主页/启动页覆盖
- 网页快照/缩略图收藏

# 组宽与每行条数解耦:档位独立成旋钮(反转 group-width-tint 的宽度推导)

group-width-tint(ADR-0004 补记 2026-12)把组宽完全交给**每行条数**推导——
单一旋钮,表单选「一行 1 条」必然把组缩回单列基准宽。用户实操反馈:拖宽的组
改一行一条后长度缩水,期望「**拖出来的长度保持住,每行条数只是组内排版**」。
grilling 两问定案(2026-12,`.scratch/group-span-decouple/`):

- 宽组 + 一行一条:每条收藏**拉满整行**(清单式;「条目保持原宽、右侧留白」弃)。
- 拖窄到装不下当前每行条数:**每行条数自动跟降**(「锁住下限拖不下去」弃)。

## Considered Options

- **A · 维持推导(v6 现状)**:单一旋钮最简、零新字段;但「长度」与「排版」在
  用户心智里是两件事,表单路径必然缩宽,反馈即本 ADR。
- **B · 档位独立(选定)**:`Group.span` 组宽档位(schema v6→v7),缺省档位从
  每行条数推导 → v6 存量**零改写迁移**(渲染逐字不变),新语义只在用户实际
  解耦时物化。
- **C · 存 px 宽度**:自由度最大;但放弃档位吸附与装箱的整数口径,拖柄松手
  吸附、导入钳界、装箱占槽全部复杂化,备份含浮点宽易碎;弃。

## Consequences

- **模型**:`spanEff = span ?? columns ?? 1`;每行条数 `= columns ?? spanEff`
  (恒 ≤ 档位,写路径保证;缺省 = 装满,收集箱拖宽即装满、与 v6 逐字一致)。
- **写路径**:拖柄/键盘 → `setGroupSpan`(装不下时 columns 自动降到档位);
  表单 → `setGroupColumns` **只升不降**(`span' = max(spanEff, cells)`,
  脱离推导时物化 span);缩画布/导入超档降档、每行条数连带降、x 按各组宽重钳。
- **渲染**:组内网格 `repeat(条数, minmax(184px, 1fr))` 由组件按生效条数注入
  (条数 < 档位 = 清单式拉满整行;装满与 v6 的 auto-fill 等价)。
- **防御**:迁移链剥离非法 span;合法 columns > 合法 span 时抬 span(宽到装得
  下,不丢排版);读取端 `groupSpanOf`/`groupCellsOf` 兜底非法值。
- **词汇**:GLOSSARY 新增「组宽档位」,「每行条数」降为纯排版旋钮;ADR-0004
  补记中「组宽由每行条数推导」口径自 v7 起失效(由本篇取代)。

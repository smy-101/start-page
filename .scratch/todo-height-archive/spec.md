# todo-height-archive:待办卡定长(高)与归档已完成

用户提案(2026-11-16):「期望 todo 卡片可以设置定长,里面内容可以滚动;
另外在正常模式下增加一个归档 icon 用于清除已完成的任务」。
问询四问定案(调高方式/缺省高度/归档可见范围/归档行为,均取推荐项)。

## 决定 1:定长 = 逐卡自由高,底缘拖调(同调宽语言)

- 待办卡新增**可选定长高** `height?: number`(px,schema v11):
  **缺省 undefined = 自适应**(现行观感:内容随长,列表约 18 行起内部滚动;
  存量零改写),只有手动调过的卡才定长。
- 钳 **[176, 720] px**(均 16 倍数):
  - 下限 176:卡头 + 约三行条目 + 添加行(卡面固定开销约 88px);
  - 上限 720:略高于现行自适应上限(列表 clamp 至 560 + 卡头/添加行 ≈ 648)。
- 交互与调宽逐字同语言(todo-card-size-color):**白板模式拖卡底缘**
  连续预览,松手 **16px 网格吸附**;键盘 **↑/↓ 步进**一格网格;
  `resizable` 门禁同宽柄(白板模式且非搜索)。
- 定长时卡面纵向 flex:卡头/添加行常驻可见,**条目列表区滚动**
  (`max-height` clamp 只在自适应态生效;定长态 `flex: 1 + min-height: 0`)。
- 高度不受画布宽钳制(画布向下无界,不似宽需收窄)。
- **钉住切换(二次问询定案,2026-11-16)**:白板模式卡头钉住钮切换
  定长 ↔ 自适应——钉住 = 以实测高吸附 16px 网格落定长;解除 = 写回
  undefined 剥离字段回自适应(store 同义不落盘)。

## 决定 2:归档 = 一键清除已完成条目,日常态开洞

- 卡头新增**归档钮**(archive 图标):点击**直接清除**该卡全部已完成条目,
  **无确认**(同现行「删条目/整卡删除均无确认」口径);无已完成条目时禁用。
- **两种模式都显示**(用户定案):日常态如提案所求;白板模式与调色/删除
  并列,能力不随模式丢失。
- **门禁再开一洞(ADR-0006 第三补记)**:删条目本锁白板,但归档是
  勾选消费的自然收尾(勾完即清,高频内容路径,同 todo-daily-add 的
  添加洞论证);未完成条目不受影响。
- store 新写路径 `clearDoneTodoItems(todoId)`:滤除 done,余条目保序重排;
  无完成条目不落盘(同义不写)。

## 边界

- 定长不进画布几何(不参与吸附/钳界/装箱——那按实测 DOM 高,自动兼容)。
- 归档不做独立归档存储(清除即删,不进收集箱——收集箱语义专属收藏)。
- 随 JSON 备份导入导出(height 逐字;导入钳回,同 width 口径)。

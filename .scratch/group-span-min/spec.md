# group-span-min:组宽档 1 统一公式(222px)

用户反馈(2026-11-16):「收藏组的最小宽度再调整的小一点,感觉有点宽了。」

## 决定:档 1 退役存量特例,统一格宽公式

- **现状与病灶**:`groupWidthOf(1)` 原返回存量单列宽 `CARD_W ≈ 389.33`
  (group-width-tint 时「存量单列宽行观感逐字不变」的刻意保留),导致
  档 1(389)与档 2(412)仅差 23px——拖柄吸附近乎无意义,且单列组偏宽。
- **定案(用户三选一拍板)**:档 1 改走统一公式 `GROUP_EDGE + k×CELL_W +
(k−1)×CELL_GAP`,档位梯度变**等差 190px**:222 / 412 / 602 / 792 / 982 /
  1172;档 1 = 单格恰装(222 内宽 184,与 CSS `minmax(184px, 1fr)` 同口径)。
  落选:240(对齐待办卡下限,仍留特例)、304(温和,档 1→2 差仅 108)。
- **连带(全部接受为既定口径)**:
  - 存量单列组观感变窄(389 → 222)——即用户诉求本身;无 schema 改动、
    无数据迁移(宽度由档位推导不存 px),旧备份恢复即新观感。
  - `nearestGroupSpan` 档 1/2 边界中点 389.33 → 317;旧档 1 宽(389.33)
    现吸附档 2。
  - 自动整理装箱:档 1 卡居中于 CARD_W 卡位槽(偏移 83 → 83/489/894),
    与档 2 卡居中偏移 191 同口径;槽宽与画布列数不变。
  - 右缘钳界:x ≤ 画布宽 − 222(缩画布重钳同径)。
- `CARD_W` 语义收窄:待办卡缺省宽 + 装箱槽宽,不再是组宽档位的底。

## 边界

- CELL_W(184)、GROUP_EDGE(38)、CSS `minmax(184px, 1fr)` 均不动。
- ADR-0004/0005 中「缺省 1 = 原 CARD_W 宽行单列」为历史决策记录,不改写。
- 流程:单会话 TDD 实现(本 spec 为纸面轨迹,不拆 tickets)。

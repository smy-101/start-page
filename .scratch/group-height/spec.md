# group-height:组定长高(与待办卡定长高对称)

用户提案(2026-11-16):「收藏组也可以像 todo 卡片那样 自适应和定高
两种模式互相切换」。问询七问定案(存储/交互面/钳界/卡面结构/折叠交互/
词条/流程,均取推荐项)。

## 决定 1:存储 = 单字段 `Group.height`,schema v12

- 分组新增**可选定长高** `height?: number`(px,schema v12):
  **缺省 undefined = 自适应**(现行观感:网格 max-height clamp 内部滚动,
  存量零改写),只有手动调过的组才定长——与待办卡 v11 逐字对称,
  不存冗余「模式」布尔。
- 迁移 v11→v12 零数据改写;运行时/导入统一修复:有限越界/非整数钳回、
  非有限/非数剥离为自适应(口径同待办卡 height)。
- 随 JSON 备份导入导出(replace 逐字恢复 + 钳回;merge 不携带组高,
  同 span/columns 排版旋钮口径)。

## 决定 2:交互面完全镜像待办卡,收集箱同样适用

- **白板模式 + 非搜索 + 非折叠**挂组底缘拖柄:连续预览 + 徽章回显,
  松手 16px 网格吸附;键盘 ↑/↓ 步进一格网格。
- **组头钉住钮**(仅白板模式可见):钉住 = 以实测高吸附 16px 网格落定长;
  解除 = 写回 undefined 剥离字段回自适应。
- **收集箱同样适用**:高度是排版旋钮非内容编辑,与折叠/调宽同权
  (它今天已享受调宽柄;组头编辑/删除仍对它隐藏)。

## 决定 3:钳界沿用待办卡 [176, 720]

- 同一画布同一套数;两侧分立命名(GROUP_H_MIN/MAX 与 TODO_H_MIN/MAX),
  canvas.test 断言同界钉住「改一侧须有意识改两侧」。
- 高不随画布宽收窄(高不参与横向几何,画布向下无界)。

## 决定 4:定长卡面 = 纵向 flex,组头常驻

- 定长时卡面纵向 flex:组头常驻(含白板编辑表单),网格区
  `flex:1 + min-height:0` 滚动,自适应态 max-height clamp 退役;空态同款。
- 不加新常驻元素:分组没有待办卡「添加行」的对口物(加收藏走对话框)。

## 决定 5:折叠与定长正交共存

- 折叠时定长暂失效(只渲染组头,无 height 样式与底柄——底柄随宽柄
  同门禁隐藏);存储的 height 保留,展开即恢复。折叠不被定长取缔。
- 钉住钮折叠时同样隐藏(与底柄同门禁,非仅白板门禁):折叠实测高
  只剩组头(钉住必钳落下界 176),「以实测高钉住」失义;解除定长
  需先展开——评审补充解读(2026-11-16),与宽柄既有模式一致。

## 决定 6:词条

- GLOSSARY 新增「**组高**」条目(与「待办卡高」对称);「待办卡高」
  _Avoid_ 同步改指「组高(分组侧同名旋钮,见『组高』)」;「分组」条目
  旋钮清单补组高。

## 边界

- 定长不进画布几何(不参与吸附/钳界/装箱——那按实测 DOM 高,自动兼容)。
- 流程:单会话直接 TDD 实现(本 spec 为问询纸面轨迹,不拆 tickets)。
